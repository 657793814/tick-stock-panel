# Wickline 项目能力分析与整合建议

> 分析对象：`wickline`（本地开源项目，开源图表/行情/回测/模拟盘平台）
> 分析目的：盘点 Wickline 的能力，提炼可借鉴或可整合到当前项目 `tick-stock-panel` 的能力与落地路径
> 文档状态：能力分析稿（供评审与后续整合决策参考）
> 生成时间：2026-11-27

## 1. 文档目的与范围

本文档只做**能力盘点与可借鉴性分析**，不包含对 Wickline 的代码移植或直接改造成本评估。结论以“与 `tick-stock-panel` 现有架构和现状对照”为前提，只给出“哪些能力值得借鉴、以什么方式、按什么优先级落地”，具体改造另行按团队二次开发 SOP 执行。

范围限定：`wickline` 主项目（含 `desktop/`、`public/`、`lib/`、`server.mjs`、`scripts/`、`test/`）与 README 已声明的公开能力。不含社区脚本库内容本身（`community/` 只是发布载体，其脚本质量不作为整合依据）。

## 2. 项目定位

Wickline 是一个**开源、免配置的图表与行情终端**：

- 覆盖加密（Binance/Binance Futures/Coinbase/Bybit/OKX）、股票/ETF/指数/外汇/期货，多周期（2m…M）。
- 内置 100 个指标 + 自定义 JavaScript 指标 + 社区脚本，带回测与策略测试。
- 绘图、价格提醒、多图表布局、回看（bar replay）、模拟盘（paper trading）。
- 面向“看盘与研究”的终端，定位接近一个轻量交易客户端，但核心仍以研究为主。

一句话：**面向通用行情/图表/回测/模拟盘的完整终端，强调免密钥、多数据源、代理兼容、脚本可分享。**

## 3. 项目结构概览

```
wickline/
  desktop/          # Electron 桌面壳：main.mjs、proxy.mjs、preload.cjs
  public/           # 静态 Web 应用（npm start 或静态托管），无构建步骤
    js/             # chart-view / app / layouts / indicators / scripts / backtest /
                    #   paper / options / screener / heatmap / news / drawing / proxy 等
    lib/             # options.mjs、screener.mjs、markets.mjs、news.mjs、calendar.mjs 等纯逻辑
    data/            # 更新后的行情/ticker 静态数据
    server.mjs + lib/ # 可选内置数据服务器（Yahoo/Nasdaq 中继、缓存、共用 Yahoo 流）
  lib/              # 纯逻辑模块（proxy、markets、calendar、clean-bars、heatmap、news 等）
  scripts/          # update-data、社区沙箱等数据/发布脚本
  community/        # 社区脚本库（发布载体，脚本质量不作为整合依据）
  test/             # 离线单元测试（回测引擎、策略 API、指标、代理、服务端等）
  public/js/backtest.js # 回测引擎（纯 JS）
```

关键实现分层：**数据层（多源 + 代理 + 缓存）→ 引擎层（回测/模拟盘/选股/选项）→ 交互层（图表/布局/绘图/面板）**。图表使用 TradingView Lightweight Charts（Apache-2.0，需保留署名）。

## 4. 核心能力盘点

按与当前项目（tick-stock-panel）最相关的维度分组盘点：

### 4.1 行情数据与数据源

- **多交易所、免密钥**：Binance 现货/期货、Coinbase、Bybit、OKX（现货+USDT/USDC 永续）；股票/ETF/指数/外汇/期货来自 Yahoo（免密钥历史与实时流）。
- **零密钥 + 代理兼容**：桌面端/`npm start` 内置 `server.mjs`（仅监听 `127.0.0.1`），全部 Yahoo/Binance/… 请求经系统代理或可设的 HTTP/SOCKS5 代理转发；页面用浏览器代理，服务端用 undici 代理。
- **行情缓存**：历史数据走缓存，增量更新，离线可跑。
- **静态站点降级**：`public/` 静态托管时，股票历史改为访客免费 Twelve Data 密钥，其余能力保留。
- 符号写法为 `SOURCE:TICKER`（如 `BINANCE:BTCUSDT`、`YAHOO:AAPL`），多源用同一符号映射。

### 4.2 指标与脚本

- **100 个内置指标**（均线、波段/通道、趋势、震荡、动量、趋势强度、量能、波动率等分类），可编辑参数与颜色，支持隐藏不删除。
- **自定义 JavaScript 指标**：Script editor 内置模板，用 `indicator(name,{overlay}) / input / plot / hline / fill / marker / ta.*` 编写，Web Worker 沙箱运行，3 秒超时、结果值校验。
- **社区脚本**：`Indicators → Community` 浏览/一键加入/发布，发布时沙箱测试，GitHub 计数点赞，版本更新提醒。

### 4.3 回测与策略测试（Strategy Tester）

- **策略 API**：`strategy(name,{capital,size,commission,slippage,pyramiding,fillOn})` + `strategy.entry / exit / onBar / close / closeAll`。
- **成交口径**：信号在 bar 收盘读取、**下一 bar 开盘价成交**（或 `fillOn:'close'` 当 bar 收盘成交），不做未来函数；止损/止盈按 bar 高低点检查，触碰时保守先算止损；佣金与滑点计入每次成交。
- **Strategy Tester**：净收益、胜率、盈亏比、最大回撤、净值曲线（对比买入持有）、多空拆分、交易清单（可点图、导出 CSV）、可编辑参数（资金、仓位、佣金、滑点、金字塔、成交时点）。

### 4.4 图表与多图表布局

- **1~8 图表**、20 种布局、可拖拽分隔条；支持同步（符号/周期/十字线）、最大化/弹出。
- **图表类型**：K线/空心/Heikin Ashi/柱/线/带标记/阶梯/面积/基准线/柱状。
- **多周期与显示**：对数/百分比刻度、对比、K线倒数计时；深浅主题 + 5 预设；可自定义配色。
- 图表库为第三方 Lightweight Charts，需保留署名。

### 4.5 绘图与价格提醒

- **绘图工具**：趋势线/射线/延长线/箭头、水平/垂直线、矩形/平行通道/文本、箭头、斐波那契回撤、measure、多空位（输入/目标）。
- **编辑与吸附**：拖拽、精确输入、磁力吸附（open/high/low/close）、线样式（实线/虚线/点线，1~20px）、价格提醒（横线触发，含声音/弹窗/通知）。
- 定位为**分析辅助**能力，不是核心交易闭环。

### 4.6 回看与模拟盘（paper trading）

- **Bar replay**：回到任意历史点逐 bar 回放，支持单步/倍速（0.5×~10×），切换 symbol/周期续播；指标与策略随 bar 出现更新。
- **Paper trading（模拟盘）**：模拟 $100,000 账户，支持市价/限价/止损单，可设止损止盈并拖动调整，订单/持仓/盈亏/成交记录面板，可调整初始资金/佣金/滑点/杠杆并重置；回放期间用独立练习账户。
- 撮合口径：实时价撮合、限价/止盈按自身价、止损按下一个成交价（带滑点）、跳空按开盘价、记账含费用与滑点。

### 4.7 选股筛选器与热力图

- **Screener**：扫描 ~3,000 大美股（或 17 个其他市场），每分钟刷新；预设想法（涨幅/跌幅、异量、52周高、突破、超买超卖、缺口、金叉死叉等）、过滤（市值/均量/板块/最低价）、信号（相对量、缺口、偏离均线/50/200 与 52 周高、RSI、1 个月变动、下次财报）、市场洞察（涨跌家数、站上均线的家数、新高新低、涨跌板块）。
- **Heatmap**：按板块分组的 Treemap，按市值与涨跌着色，支持美国 + 17 个其他市场 + 加密分类。

### 4.8 新闻、日历与期权（附加能力）

- **新闻**：约 45 源、每 30 秒刷新，按市场区域分组，按“市场影响度”排名（多源合并、大公司/异动加权），Hot/Breaking 标记，联动个股。
- **日历**：约 60 国经济日历 + 财报日历，按影响排序、倒计时、含 EPS/惊喜。
- **期权**：K线符号的期权链（美股/ETF 来自 Yahoo 约 15 分钟延迟、比特币/以太来自 Deribit 实时），到期结构、IV、预期波动（straddle/±1σ）、put/call 比、最大疼痛、Greeks（Black-Scholes 4% 无风险利率）、异常活跃合约。

### 4.9 社区脚本共享与发布

- 通过 GitHub issue 表单发布脚本 → 在容器内无网络沙箱测试 → 通过则加入 `community/`、可被所有 Wickline 加入、GitHub 计数点赞、版本更新提醒；编辑器里有模板与社区脚本入口。

### 4.10 工程化

- **脚本沙箱**：Web Worker 隔离，禁止网络/存储/DOM，结果值校验（值数量、大小），3 秒超时防卡死。
- **代理**：桌面 session + 服务端 undici 双层代理，改动即时生效，支持系统/HTTP/SOCKS5，不支持带密码代理。
- **i18n**：9 种语言 UI，跟随系统语言。
- **桌面/静态双形态**：Electron 桌面（`npm run desktop`）与纯静态 `public/`（`npm start`）同源能力。
- **测试**：离线单元测试覆盖回测引擎、策略 API、全部指标、沙箱与结果校验、数据解码、服务端等；另有需联网的 e2e。

## 5. 与当前项目 tick-stock-panel 的能力对照

先明确 `tick-stock-panel` 现状（作为对照基准）：

- **定位**：多市场（A股/港股/美股）智能量化工作台（fork 二开版），Polars 引擎、Python 3.11+、Node 20+、React 18、Docker 单容器自托管。
- **已具备**：策略引擎（自定义策略 + AI 生成）、回测（引擎/订单引擎/持仓/因子/ walkforward/分钟回放/稳健优化）、指标流水线（68 列指标与信号）、因子平台（DSL 因子 + 检验组合）、因子挖掘、市场环境/异动监控/监控中心（四类规则 AND/OR + 语音 + 飞书）、个股分析、连板梯队、复盘海报、插件化数据源、多市场隔离、开放接口（65 端点 + Token 六档权限）+ MCP 服务器（12 工具）。
- **当前推进阶段**：quantjourney-bt 能力提取与整合（整合方案已落盘，P0-1 订单模式执行引擎编码中，覆盖 fill engine、slippage/commission、最大成交量参与、blotter、fill_at；下一步完成订单引擎模块及相关测试）；另有虚拟账户（模拟盘）设计稿（未实现）、纸面回放与多市场计划。

对照结论：**Wickline 的价值不在与 tick-stock-panel 同构，而在“交互形态与执行口径”的补充**——尤其是策略 API 语义、撮合/模拟盘口径、数据代理与缓存模式、脚本/指标沙箱机制。tick-stock-panel 已有回测、因子、监控、数据源插件，这些是已有或规划中的能力，因此借鉴应以“**对齐口径/补交互/补机制**”为原则，避免重复自建已有能力。

## 6. 可借鉴的能力（按优先级）

以下按“与当前项目契合度 + 落地改动量”排序。具体改造需按团队二次开发 SOP 单独评估。

### P0 —— 优先借鉴：策略 API 语义 + 撮合/模拟盘口径（最直接，改动最小）

1. **策略 API 的“信号→订单→成交→统计”语义**
   - 借鉴点：Wickline 的 `strategy.entry/exit/onBar/close` + `fillOn` 干净接口、信号收盘读价、下一 bar 开盘成交、止损/止盈按高低点保守判断、佣金/滑点计入成交。
   - 契合点：与当前 P0-1 订单引擎（fill engine、slippage/commission、blotter、fill_at）和 paper-trading-plan 的撮合规则天然对齐；可作为**订单引擎与策略接口的语义约定参考**，统一“成交时点、成本口径、止损保守规则”。
   - 落地建议：把 Wickline 撮合规则表（即时市价单/次日开盘单/当日收盘单、顺延、涨跌停、T+1、raw 价口径）作为订单引擎撮合规则的**口径参考**，与现有 `order_engine.py`/`portfolio_book` 对照后补充或对齐，而非替换。

2. **Strategy Tester 的统计与展示结构**
   - 借鉴点：净收益、胜率、盈亏比、最大回撤、净值曲线（对比买入持有）、多空拆分、交易清单（点图/导出 CSV）的结构化呈现。
   - 契合点：与当前回测研究视图（因子/策略/分钟回测、因子归因、证据输出）互补；可作为策略研究统计的输出规范与界面结构参考，复用现有回测统计能力，只补展示口径。

### P1 —— 次优先借鉴：数据代理/缓存模式 + 脚本沙箱机制

3. **多源数据“零密钥 + 代理 + 缓存 + 增量更新”接入模式**
   - 借鉴点：Wickline 用系统/HTTP/SOCKS5 代理转发 Yahoo/Binance 等请求，内置 server 只监听本机，历史数据缓存、增量更新、离线可跑；静态站点降级到 Twelve Data 密钥。
   - 契合点：与 tick-stock-panel **插件化数据源**（`data_providers/registry/capabilities`、`custom/`）完全同构。可作为**新增数据源插件接入的参考范式**（代理接入、本机 server、缓存与增量、降级方案），降低新数据源接入成本。
   - 落地建议：参考其“代理接入 + 本机 server + 缓存 + 能力路由”结构，补到数据源插件开发文档/模板中，而非直接搬代码。

4. **脚本/指标运行器的“沙箱隔离 + 结果校验 + 资源上限”机制**
   - 借鉴点：Wickline 脚本跑在 Web Worker 中，禁止网络/存储/DOM、结果值校验、3 秒超时防卡死。
   - 契合点：tick-stock-panel 已有脚本沙箱/结果校验类能力（自定义信号、脚本运行校验），可作为**运行器安全模型的参考**，把“隔离 + 校验 + 超时”收敛成统一规则。
   - 落地建议：把 Wickline 的沙箱安全模型（隔离范围、结果校验、执行超时）沉淀为当前项目自定义脚本/指标的运行规范。

### P2 —— 观察/可选借鉴：回放交互、绘图提醒、选股筛选、期权链

5. **Bar replay 的交互与数据续接设计**
   - 借鉴点：Wickline 逐 bar 回放（单步/倍速/跨 symbol/周期续播）、指标与策略随 bar 更新。
   - 契合点：与当前 paper-replay 计划相邻；可作为回放流水线的**交互与续播数据流设计参考**。
   - 落地建议：仅在 tick-stock-panel 已有回放能力不足以支撑时参考，作为设计选项，不单独建设。

6. **绘图、价格提醒与市场洞察类分析辅助**
   - 借鉴点：绘图工具（趋势线/斐波那契/多空位）、价格提醒（横线触发）、筛选器与热力图的市场洞察。
   - 契合点：tick-stock-panel 已有复盘海报、监控中心、看板，这些属于“分析辅助”，而非核心交易闭环。
   - 落地建议：视 tick-stock-panel 现有复盘/监控覆盖，选择性借鉴其交互与信号计算思路，避免重复建设核心交易能力。

7. **期权链与 Greeks 能力**
   - 借鉴点：Wickline 的期权链（Deribit/Yahoo）、IV、预期波动、最大疼痛、Greeks（Black-Scholes）。
   - 契合点：tick-stock-panel 当前未覆盖该能力，属扩展项。
   - 落地建议：可作为后续数据源能力扩展候选，但依赖特定市场接口，优先级低、需按数据源插件能力路由单独评估；本次不优先。

## 7. 不建议直接整合 / 需适配的点（风险与边界）

1. **回测引擎不兼容，不能直接替换**
   - Wickline 回测引擎是纯 JS（`public/js/backtest.js`）+ 原生实现，与 tick-stock-panel 的 Polars/Python 回测引擎不兼容。仅借鉴其**策略 API 语义与撮合口径**，不搬引擎代码。

2. **图表库为第三方，需保留署名**
   - 图表基于 TradingView Lightweight Charts（Apache-2.0），要求保留署名。tick-stock-panel 前端为 React + 已有图表体系，直接引入需评估第三方依赖与署名合规，风险较高，不作为优先整合项。

3. **交易终端定位与本项目目标存在偏差，仅作研究辅助**
   - Wickline 面向通用交易终端（含实盘意图、K线实时跟随、账户资金管理等），tick-stock-panel 定位量化研究工作台（研究为主、不实盘）。两者定位不同，仅借鉴其中与量化研究相关的能力，不照搬其交易终端形态。

4. **代理配置不适合直接搬入 Python 后端**
   - Wickline 的代理在 Node/Electron/undici 层实现，与 tick-stock-panel Python 后端无关，仅借鉴其“代理接入 + 缓存”的思路，不直接搬代码。

5. **社区脚本库质量不作为整合依据**
   - `community/` 是发布载体，其脚本内容质量、与量化口径无关，不纳入整合范围。

| P2 | Bar replay 交互、绘图/提醒、选股筛选、期权链 | 视现有复盘/回放/监控覆盖决定 | 选择性设计选项 |

## 9. 结论

Wickline 的核心能力是**“免密钥、多数据源、脚本可分享的图表/行情/回测/模拟盘终端”**。对 `tick-stock-panel` 而言，最有价值、改动最小的借鉴集中在三块：**策略 API 与撮合口径**（直接对齐当前 P0-1 订单引擎与模拟盘设计）、**数据源代理/缓存接入范式**（对齐现有插件化数据源）、**脚本/指标沙箱安全模型**（补运行规范）。回放、绘图、筛选、期权链等能力可作辅助或后续扩展，但受定位差异与第三方依赖限制，不作为优先项。建议按 P0 → P1 → P2 的顺序，以“对齐口径/补交互/补机制”为原则落地，并沿用团队二次开发 SOP 与验证闭环要求。
